# QR จ่ายบิล MEA / MWA — วิธีที่ถูกต้อง

> repo นี้เป็น **public** — เอกสารนี้ใช้ค่าตัวอย่างสมมติทั้งหมด
> **ห้ามใส่เลข CA / เลขบิล / account_code จริงลงไฟล์ใดๆ ใน repo**

## สรุปสั้น

สร้าง QR ด้วย **EMVCo tag 30** (ไม่ต้องเลียนแบบรูปแบบบาร์โค้ดบนบิล) โดยใช้

| ฟิลด์ | MEA (ค่าไฟ) | MWA (ค่าน้ำ) |
| --- | --- | --- |
| Biller ID (`01`) | `MEA_BILLER_ID` | `MWA_BILLER_ID` |
| Ref1 (`02`) | `mea_electric.ca` เติม `0` **ท้าย** ครบ 10 หลัก | `mwa_water.account_code` (10 หลักพอดี) |
| Ref2 (`03`) | `mea_electric.bill_no` เติม `0` **หน้า** ครบ 12 หลัก | `mwa_water.bill_number` เติม `0` **หน้า** ครบ 12 หลัก |
| ยอด (`54`) | `mea_electric.paid` | `mwa_water.gross_amount` |
| สกุลเงิน (`53`) | `764` | `764` |
| ประเทศ (`58`) | `TH` | `TH` |
| AID (`30`→`00`) | `A000000677010112` | `A000000677010112` |

**Ref2 จำเป็น** (ตัดออกแล้วสแกนไม่ผ่าน) แต่ **ไม่ต้องมีวันครบกำหนด** —
นี่คือกุญแจที่ทำให้สร้างจาก collector DB ได้ครบ เพราะ DB ไม่เก็บวันครบกำหนด

โค้ด: `src/lib/thai-qr.ts` (encoder) + `src/lib/bill-qr.ts` (ประกอบจาก DB)

## วิธีหา Biller ID (ทำครั้งเดียวต่อผู้ให้บริการ)

Biller ID เป็น **ค่าคงที่ของผู้ให้บริการ** ไม่เปลี่ยนตามบิล ตั้งครั้งเดียวใช้ตลอด

1. เปิดบิล (e-Bill PDF) แล้ว screenshot **QR ที่มีป้าย "QR Cross Bank"**
2. ถอดด้วยโปรแกรม (ดูสคริปต์ด้านล่าง) → ได้สตริง `|<BillerID>\r<...>\r<...>\r<...>`
3. เอาฟิลด์แรก (15 หลัก) ไปตั้งเป็น `MEA_BILLER_ID` / `MWA_BILLER_ID`

> ⚠️ **ห้ามอ่านตัวเลขใต้บาร์โค้ดด้วยตา** — เคยทำแล้วได้เลขผิด เพราะเลขใต้
> บาร์โค้ดจัดฟิลด์ไม่เหมือน QR และอ่านจากภาพผิดพลาดง่าย ต้องถอด QR ด้วยโปรแกรม

## รูปแบบบาร์โค้ด/QR บนบิล (ไว้อ่านค่า ไม่ใช้สร้าง)

QR บนบิลเก็บสตริงแบบบาร์โค้ด คั่นฟิลด์ด้วย **carriage return (`\r`, 0x0D)**

```
|<BillerID>\r<Ref1>\r<Ref2>\r<ยอดเป็นสตางค์>
```

- `\r` **มองไม่เห็นใน terminal** เพราะเลื่อน cursor กลับต้นบรรทัด
  ครั้งแรกจึงเข้าใจผิดว่าเป็นตัวเลขยาวติดกัน → **ต้อง dump hex เสมอ**
- ยอดเป็น **สตางค์** ไม่มีจุดทศนิยม (`2634` = 26.34 บาท)
- ฟิลด์ในบาร์โค้ด **ไม่ตรงกับ Ref แบบ EMVCo**:
  - MEA: Ref2 ในบาร์โค้ด = `0` + เลขบิล + **วันครบกำหนด(DDMMYY พ.ศ.)**
  - MWA: Ref1 ในบาร์โค้ด = `2` + account_code + bill_number + `4`
    (ยัดสองค่ารวมกันแล้วห่อด้วย marker) และ Ref2 = วันครบกำหนด + เลขอื่น
  - ส่วนที่เกินพวกนี้ **ไม่ต้องใช้กับ EMVCo** พิสูจน์ด้วยการสแกนแล้ว

## สคริปต์ถอด QR จากภาพ

ติดตั้ง**นอก repo** เพื่อไม่ให้ dependency ปนกับโปรเจกต์

```bash
mkdir -p /tmp/qrdec && cd /tmp/qrdec
echo '{"name":"qrdec","private":true}' > package.json
bun add jsqr pngjs
```

```js
// dec.mjs
import { readFileSync } from 'node:fs'
import { PNG } from 'pngjs'
import jsQR from 'jsqr'

const png = PNG.sync.read(readFileSync(process.argv[2]))
const r = jsQR(new Uint8ClampedArray(png.data), png.width, png.height)

console.log('text:', JSON.stringify(r.data)) // JSON.stringify เพื่อให้เห็น \r
console.log('hex :', [...r.data].map((c) => c.charCodeAt(0).toString(16).padStart(2, '0')).join(' '))
console.log('fields:', r.data.replace(/^\|/, '').split('\r'))
```

ถ้า QR เล็กจนอ่านไม่ออก ให้ upscale ภาพ (nearest-neighbour) แล้วลองใหม่

## วิธีทดสอบว่าสร้างถูก (สำคัญ)

QR จ่ายเงินผิด = เงินไปผิดที่ ต้องพิสูจน์ ไม่ใช่เชื่อว่าถูก ใช้ **ตัวควบคุม**:

1. สร้าง QR จากสตริงที่ถอดมาจากบิล **ทั้งสตริงเป๊ะๆ รวม `\r`** = ตัวควบคุม
   ยืนยันด้วยโปรแกรมว่า decode กลับได้ byte-identical กับต้นฉบับ
2. สแกนตัวควบคุม → ถ้าไม่ผ่าน ปัญหาอยู่ที่การ render QR ไม่ใช่ข้อมูล
3. สแกนตัวที่สร้างเอง (EMVCo) เทียบกับตัวควบคุม
4. เปลี่ยน **ทีละตัวแปร** (มี/ไม่มี Ref2, เติมศูนย์/ไม่เติม, Biller 13/15 หลัก)
   เพื่อรู้ว่าฟิลด์ไหนจำเป็น

**ทดสอบกับบิลที่จ่ายแล้ว** — ถ้าแอปขึ้น "ชำระแล้ว" ถือว่าผ่าน เพราะพิสูจน์ว่า
resolve เลขอ้างอิงได้ถูก โดยไม่ต้องเสียเงินซ้ำ

## ผลทดสอบสแกนจริง (แอปธนาคารไทย)

| สิ่งที่ทดสอบ | MEA | MWA |
| --- | --- | --- |
| QR บนบิลจริง | ✅ | ✅ |
| สตริง byte-identical กับบิล (มี `\r`) | ✅ | ✅ |
| สตริงบาร์โค้ดแต่ **ไม่มี `\r`** | ❌ | ❌ |
| EMVCo + Ref ที่เดาเอง | ❌ | ❌ |
| EMVCo + Ref จากบาร์โค้ดตรงๆ (มีวันครบกำหนด) | ✅ | ❌ |
| EMVCo ไม่มี Ref2 | ❌ | ❌ |
| **EMVCo + Ref2 = `0`+เลขบิล (ไม่มีวันที่)** | ✅ | — |
| EMVCo + Ref2 = `0`+เลขบิล+`000000` | ✅ | — |
| **EMVCo + Ref1=บัญชี, Ref2=เลขบิล** | — | ✅ |
| EMVCo + Ref2 = เลขบิลเติม 0 ครบ 12 | — | ✅ |
| EMVCo + Ref1 ตัด marker ท้ายออก | — | ❌ |
| EMVCo + Ref2 = แค่วันครบกำหนด | — | ❌ |
| EMVCo + Biller 13 หลัก (ไม่มี suffix) | — | ❌ |

### บทเรียน

- **MEA และ MWA ใช้กติกาเดียวกัน**: Ref1 = เลขบัญชี, Ref2 = เลขบิล
  ตอนแรกคิดว่า MWA ไม่รองรับ EMVCo เพราะลองด้วย Ref ที่ลอกจากบาร์โค้ดมาตรงๆ
- ตัวเลขห่อ/วันที่ในบาร์โค้ดเป็นเรื่องของ **รูปแบบบาร์โค้ด** ไม่ใช่ Ref จริง
- อย่าเชื่อ `console.log` กับข้อมูลไบต์ — ใช้ `JSON.stringify` + hex

## การตั้งค่า

```
MEA_BILLER_ID   # 15 หลักจาก QR บิลค่าไฟ — ไม่ตั้ง = ซ่อน QR ค่าไฟ
MWA_BILLER_ID   # 15 หลักจาก QR บิลค่าน้ำ — ไม่ตั้ง = ซ่อน QR ค่าน้ำ
QR_SIGN_SECRET  # secret sign URL รูป QR (ไม่ตั้ง = ใช้ BETTER_AUTH_SECRET)
```

**ไม่มี default โดยเจตนา** — ไม่ตั้ง = ซ่อน QR (fail-safe) เพราะ QR ผิด
อันตรายกว่าไม่มี QR และ repo เป็น public

## สถาปัตยกรรมรูป QR ในการ์ด LINE

LINE ต้อง fetch รูปเองจากภายนอกโดยไม่มี session แต่ `src/middleware.ts`
บล็อกทุก path จึงต้องเปิด `/api/qr` เป็น public แล้วกันด้วย **HMAC**:

- payload ฝังอยู่ในตัว token (`<base64url payload>.<ลายเซ็น>`)
- endpoint ไม่แตะ DB → **enumerate เลขบิลไม่ได้**
- แก้ payload แม้อักขระเดียว ลายเซ็นไม่ผ่าน → 404
- ไม่เช็ค CRC เพราะรูปแบบบาร์โค้ดไม่มี CRC (ต่างจาก EMVCo) HMAC พอแล้ว

ดู `src/lib/bill-qr.ts` (`encodeQrToken`/`decodeQrToken`) และ
`src/pages/api/qr/bill.png.ts`
